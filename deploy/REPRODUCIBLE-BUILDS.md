# Reproducible CloudOps images

Run `bash deploy/build-image.sh local-name:tag` from the repository root. It builds **committed HEAD**, not workspace edits. Jenkins uses the same entrypoint. Run `bash tests/integration/compare_builds.sh` to compare two fresh, cache-free builds; logs and image IDs are saved under `reports/reproducibility/`. This command does not publish or deploy.

## Build contract

- CPython 3.12.15 / Debian trixie, official Python linux/amd64 manifest `sha256:6b1f85a08c199d29d5b6d71ab9c27bd5b3b393492e01216a15758ff69c4be8b8`, reviewed from the official image index (source revision `2a3b794c223ab067d122719541cdd54a068732a5`). The Jenkins Python test image uses the same digest.
- Exact versions and SHA-256 wheel hashes for every direct and transitive dependency in `requirements.txt`. `requirements.in` records upgrade constraints. Only CPython 3.12 Linux amd64 wheels are supported by this lock; unsupported platforms fail closed.
- No apt upgrade at build time. OS security fixes normally arrive through a reviewed base-digest update. This base still contains fixable HIGH `CVE-2026-103111`; the Dockerfile applies Debian's exact `libpcre2-8-0=10.46-1~deb13u3` amd64 package, with SHA-256 verified against Debian's signed apt index (`e226f661d918f04daf38cdbc4806b7ed7d6ef95c7eb0ade692fc350e31970040`). No package resolution occurs during builds. Timestamp-bearing dpkg logs are removed. Missing or changed package bytes fail the build. Trivy reporting and fixable HIGH/CRITICAL gates remain mandatory.
- Pinned Docker CLI/Buildx container, BuildKit daemon and Dockerfile frontend. Each invocation creates a uniquely named isolated builder and removes only that builder afterward. Jenkins needs access to the host Docker socket and permission to create BuildKit containers; no Jenkins workspace bind mount is needed.
- Git archive supplies only committed application build inputs, canonical file modes and commit metadata. Commit time supplies `SOURCE_DATE_EPOCH`; the exporter rewrites layer timestamps. No wall-clock timestamp, Jenkins build number or variable version label is injected. UID/GID stay at the prior image's 999/999 and shadow account dates are deterministic; pip bytecode generation is disabled. The rebuildable ldconfig auxiliary cache is removed because it records filesystem inode data; the runtime linker cache remains intact.
- One platform (`linux/amd64`), Docker exporter, no automatically generated provenance/SBOM attestations (which include build timestamps). Existing scanner artifacts remain enabled. The Docker image ID is the comparison contract; a registry/index digest is a separate value and deployment remains pinned to the verified ECR digest.

Docker documents the timestamp mechanism at https://docs.docker.com/build/ci/github-actions/reproducible-builds/ and https://github.com/moby/buildkit/blob/v0.28.0/docs/build-repro.md.

## Updating safely

1. Open an update branch. Inspect the official `python:3.12-slim` index with `docker buildx imagetools inspect`; review the linux/amd64 manifest, Python/Debian versions, upstream source revision and available security fixes. Pin the approved child digest in Dockerfile and Jenkinsfile together. Remove the explicit PCRE2 patch when the new base includes that fix; never downgrade a newer base package. If an urgent fixed package is needed before the official image updates, review its version, architecture, dependencies and SHA-256 from Debian's authenticated package index and pin all required package artifacts. Review CLI, BuildKit and frontend digest changes separately.
2. With the newly pinned base and `--platform linux/amd64`, mount this checkout at `/src`, use `/src` as the working directory, and run `python deploy/lock-dependencies.py`. The resolver downloads binary wheels into a fresh temporary directory and writes versions/hashes. Review all dependency changes and upstream release/security notes. Do not regenerate the lock during normal CI.
3. Commit the update before building. Run pytest, pip check, Jenkinsfile/shell checks and `bash tests/integration/compare_builds.sh`. Run the unchanged Gitleaks/SonarQube/Trivy gates before release; archive the comparison and scanner evidence. Unfixed findings require the existing documented risk review.
4. Merge only after review. Existing immutable tags are never replaced. A historically non-reproducible commit whose ECR image differs still fails; remediation is a new reviewed source commit, not deleting the tag or weakening comparison.

The application EC2 role policy also needs the reviewed `DescribeTargetHealth` statement applied manually: `Resource: "*"`, restricted to the validated `AWS_REGION`. AWS does not support resource-level permissions for this action (https://docs.aws.amazon.com/service-authorization/latest/reference/list_elbv2.html). Canary SSM preflight calls this API on the application instance before manual approval, and deployment repeats it before creating a candidate. Verification and rollback stop immediately on an API error; only successful unhealthy responses are polled. This repository change does not apply IAM policy or deploy resources.
