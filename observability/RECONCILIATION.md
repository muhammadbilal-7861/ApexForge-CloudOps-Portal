# Reconcile the installed project

Inventory approval is a gate before service restarts, new images, mount changes or merge. Installed versions, project paths, service names, data-source UIDs and storage locations are currently UNKNOWN. This is a reconciliation plan, deliberately not a second standalone Compose stack.

1. Run `scripts/inventory.sh` via SSM on the existing monitoring host. Resolve ownership if multiple projects exist. Inspect configuration contents privately; never commit environment dumps.
2. Back up actual Prometheus TSDB, Grafana database/plugins, Loki storage/configs off-instance using consistent service-specific snapshots (quiesce if required). Record restore procedure and permissions. Export dashboards and data-source UIDs without credentials.
3. Record for Prometheus, Grafana, Loki, Alertmanager and optional exporters: container/project/service, config path, image tag/image ID/RepoDigest, mount source/destination, UID/GID, network, bound ports, command and health. Obtain available digests with `docker image inspect --format '{{json .RepoDigests}}' <image-ID>`. Local images may have no registry digest. Pin reviewed immutable `repository@sha256:...` references, initially preserving installed versions. No guessed image pins are supplied. New services and Alloy require a separately reviewed version/digest and verified upstream checksum/signature.
4. Reuse the exact existing `docker compose -p <project> -f <existing-file>` invocation and overrides. Preserve all mounts, flags, storage names and Loki schema/storage configuration. Never `down -v`, prune, rename volumes or initialize replacement empty storage.
5. Merge example scrape jobs and CloudOps rules into existing Prometheus configuration, preserving other jobs, rules, remote-write and routing. Adjust absolute file paths and Alertmanager/blackbox addresses to inventory. The example uses host loopback for these optional services; they must use host networking or loopback-published ports. No service is installed by the example.
6. If IMDSv2 fails in a bridge network, prefer Prometheus host networking with `--web.listen-address=127.0.0.1:9090`, removing incompatible published ports. Preserve other flags including TSDB path. Check Grafana's route: localhost is container-local and Docker DNS names may cease to work. Host-network Grafana can use loopback; otherwise retain a reviewed private container route/proxy. Do not expose the UI to solve routing. Grafana publication should bind `127.0.0.1:3000`; Loki private:3100; Alertmanager loopback:9093; blackbox loopback:9115.
7. Validate a private candidate with matching-version binaries and `docker compose ... config --quiet`. Effective config output can disclose secrets. Diff candidates against backups. Never overwrite originals without review. Reload Prometheus with SIGHUP after installing reviewed config/rules and check `prometheus_config_last_reload_successful == 1`. For required image/mount changes use only targeted `up -d --no-deps <existing-service>`, retaining ownership/flags. Do not restart the entire stack.
8. Prefer dashboard JSON import selecting existing sources. Provisioning is opt-in: substitute existing names, UIDs, org ID, URLs; inspect/back up current provisioning and avoid default-source changes or delete/prune. For file provisioning replace `${DS_PROMETHEUS}`/`${DS_LOKI}` in a deployment copy with actual UIDs (`__inputs` applies to UI import). Check dashboard UID collisions and assign a new UID if needed.
9. Verify queries, logs and health. Retain backups through maintenance validation. Rollback restores original configs, reviewed image pins and mounts, preserving data. Schema upgrades require the original version's restore plan.
